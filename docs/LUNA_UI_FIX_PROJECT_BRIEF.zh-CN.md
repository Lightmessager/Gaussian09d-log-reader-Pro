## 1. 项目目标

让用户能在应用内命名、重命名及删除项目；让分子视图正确显示元素符号；提供独立、可发现的反应路径搭建窗口，在窗口中磁吸拼接**整条路径的反应式及各阶段能量表达式**，手动选定物质/作业后用预设自动计算过渡态和产物相对能量，允许自定义零点，并利用物质关系网快速部署路径；在搭建系统中给物质加星，图上也可从路径点右键进入该物质选择；改善深色界面的文字与控件辨识度。交付对象是当前源码。四项工作分开实施、分开验收，最后做一次集成检查。

启动前先读 `AI_HANDOFF.md`、`docs/ENERGY_PROFILE_REPLICA_GUIDE.zh-CN.md`、`docs/energy-profile-replica-progress.md`、`docs/contracts.md`。以上文件中的历史阶段状态以较新的记录为准；本项目书针对用户在 v.1.0 后指出的四个问题。

## 2. 现状与边界

- `ui/main_window.py` 的项目名来自 `.grproj` 路径名，首页最近项目只有打开入口。`storage/preferences.py` 保存最近项目列表。`services/session.py` 串行管理仓库、恢复与保存；项目文件正打开时不可直接在 UI 线程改名或删除。
- `ui/analysis_pages.py` 的 `StructureCanvas` 用局部符号字典，未包含 B，缺项会显示原子序数。原子序数仍是结构数据的正确内部表示。
- `ui/path_editor.py` 当前 `NewPathDialog` 只能选择已有节点或创建空路径。`ui/main_window.py` 的节点、路径编辑分散在菜单中；`services/controller.py::add_node` 创建的节点初始表达式为空。`core/models.py` 已有 `NodeRole`、`EnergyRef`、`ProfileNode`、`PathEntry`、`ReactionPath`。
- `ui/expression_editor.py` 已有组分构建器、拖入物种、专家文本与显式保存；`core/expressions.py` 的 AST 是唯一表达式语义。`resources/plot/profile.js` 的点选事件携带 path/entry/node UUID，`ui/profile_view.py` 会校验项目、修订和 render_id。L4 的磁吸编辑及右键加星须接在这些入口，不另造计算器。
- `resources/themes/lavender_sunset.json` 同时含应用深色 tokens 和能量工作台深色 tokens。主题经 `ui/theme.py` 等处映射到 Qt 与图表；不要只改一张截图使用的 CSS。

科学和存储边界：项目、来源、作业、节点和路径均按 UUID 关联；节点标签或文件名不充当身份。能量引用保留来源文件、作业、能量类型和来源行；缺值不可补零。内部值仍用 Hartree。用户指定的 Gibbs 计算量为**同一 Gaussian 作业的 `SCF Done + Thermal correction to Gibbs Free Energy`**；两项不可跨文件、跨作业或跨计算条件拼接，单独的 SCF、热校正与合成 Gibbs 量必须明确区分。现有直接读取的 Gaussian 总量行用于交叉核查，语义调整须经 L4 科学接口复核。保留 SQLite v1、来源校验及多路径比较算法；如现有表达式语义不足，先按第 4 节停下复核。物质关系是用户声明的拓扑资料，不自动推断化学反应或能量；星标是物质的选择与检索标记，不参与计算。路径反应式的计量系数与能量表达式的系数须逐项显式确认；零点是有来源或明确标作手工输入的参考表达式，不是给缺失值填零。

### L3：项目命名、重命名与删除

**目标**：用户从项目首页和项目菜单管理 `.grproj` 项目，不必去资源管理器手动改文件。

1. 新建项目时允许输入显示名称；第一次保存时用该名称预填文件名。已有项目的“重命名”明确作用于 `.grproj` 文件名，界面标题随之更新，项目 UUID 和科学内容不变。只允许同目录改名，避免相对来源路径因移动目录改变。
2. 最近项目项提供三个动作：“打开”“从最近项目移除”“删除项目文件…”。移除只更新本机偏好；删除须展示目标完整路径和清楚的确认文案，且只处理被选中的 `.grproj`，绝不删除 `.log/.out`、导出目录或其他项目。
3. 文件改名/删除放在 `SessionBackend` 的串行工作流中：先处理未保存修订与恢复状态，释放当前仓库连接，再执行文件操作；失败时保留旧路径、旧最近列表和可重试状态。当前项目被删除后回到未打开项目状态；非当前项目操作不干扰当前编辑。
4. `LocalPreferences` 增加按规范化路径移除/替换最近项目的方法；最近菜单与首页立即刷新。确认目标不存在、是目录、只读或被占用时给出可理解的错误。

**验收**：新项目命名并保存；已保存项目改名后在新进程打开，UUID、来源和路径内容一致；最近列表无旧路径；“仅移除最近”不删磁盘文件；删除指定项目后其他 `.grproj` 及日志仍在；取消与失败均不显示成功。

### L4：整条路径反应式、磁吸计算与物质关系网

**目标**：用户从能量剖面页进入独立窗口，先拼出完整的“反应物 → 过渡态/中间体 → 产物”反应式，再为每一阶段选择具体物质、Gaussian 作业、能量类型和运算方式。选择计算预设与零点后，由现有计算链自动得到各节点相对能量，特别清楚展示过渡态与产物相对能量。物质可在搭建系统中加星并用于关系网筛选/快速部署；从图上右键路径点可进入相关物质的选择。磁吸是编辑交互，最终仍生成现有 `ExpressionDocument`、`ProfileNode` 和 `ReactionPath`，不另建能量计算规则。

`docs/design/l4-reaction-builder-concept-v1.png` 仅说明布局和交互气氛；图中的数值、分子及旧的直接“加星”菜单不定义计算规则。真实表格的只读核对与待确认项见 `docs/l4-energy-workbook-audit.zh-CN.md`。以下 1.3 版文字优先。

#### L4.0 身份、保存和最小接口

1. **物质卡**是用户确认的概念实体，分配独立 UUID 和可编辑显示名，可关联一个或多个明确的 `(source_file_id, job_id)` 候选；同名、同文件名或相似结构绝不自动合并。**计算节点**仍是 `ProfileNode.id`，持有一个阶段的体系能量表达式和角色；**图上路径点**是 `PathEntry.id`，同一个计算节点可被多条路径引用。**路径反应网络**按 path UUID 记录阶段组成、显示顺序及明确连接 UUID；允许分支与回汇，显示顺序不定义连接关系。物质、阶段、连接、计算节点、路径点身份不得混用。
2. 物质关系网是项目内的有向图：顶点为物质 UUID，边有 UUID、起点、终点及用户选定的“前驱/后继”关系和可选说明。边只表达用户记录的拓扑，不等同已证实的反应机理。每张物质卡显示自己的直接邻居及通往它们的边；全局图只是这些局部关系的合并视图。允许分支与环，但自动部署不得猜选分支或无限追环。物质与某个计算节点的关联须显式记录；组合节点可关联多张物质卡。
3. **v1 兼容落盘方案**：物质、关系边、物质星标、物质到节点的关联，以及按 path UUID 保存的整条反应式与预设选择，放入项目级、带版本号的 `workspace_state["reaction_network_v1"]`，由专门的读写/校验接口管理。真正参与计算的各阶段表达式仍以 `ProfileNode.expression` 为准，当前零点仍以 `ReactionPath.reference_expression` 为准；预设记录仅供重建和解释，不能成为第二套数值真相。全部随项目修订、撤销/重做、恢复及 `.grproj` 保存，不放入本机偏好。严格校验 UUID、现存对象的关联、计量系数、边数量和载荷大小；已移除来源造成的悬空引用要显式标记为不可部署的历史关联，保留原 ID 与诊断，不静默丢边。若现有 v1 编解码或控制器事务无法安全保证这些条件，在改动 SQLite schema 或科学模型之前先提交最小接口与迁移方案，按第 4 节停止复核。
4. **配平与公共参考规则（已采纳）**：物质卡可录入分子式，阶段组成保存物质 UUID 与计量系数。每条阶段图边都要独立确认并记录核对说明；边两端的分子式与计量向量齐全时，程序自动验证元素总数守恒，未配平即拒绝进入累计路径。若分子式不全，用户须对该边明确确认组成可比并填写依据；缺公式不能视为自动配平。元素守恒不推断物种、机理、补偿能量或计算作业。能量账本仍需用户逐项给出来源、符号、系数和原因。
5. 星标按 **物质 UUID** 生效，操作位置以反应路径搭建系统的物质库、物质卡和关系网为主：先明确选中物质，再“加星 / 取消星标”。同一物质用于多条路径时星标随物质出现；一个计算节点含多种物质时，不能把整节点误当成单一物质。星标用于物质筛选、候选排序与图上提示，不改变能量值、节点顺序、角色、来源或路径颜色。删除路径点不删除该物质的星标；删除物质时按物质删除流程处理星标。本条替代 1.1 版按 `PathEntry.id` 加星的设计。

#### L4.1 入口、窗口与可发现性

- 在能量页顶层工具条增加“编辑反应路径…”入口；原有路径菜单保留快捷操作。独立 `QDialog` 或等效顶层窗口可切换现有/新路径、名称、颜色、能量类型、单位、计算预设与零点。
- 左栏为“已导入文件/作业”及可加星的“物质库”：文件展开后列出作业序号、终止状态、SCF/Gibbs 等实际候选值和来源行；同一文件的不同作业可单独选。中栏上部是**完整反应式轨道**，可在反应物侧放多个物质、在过渡态/中间体阶段放完整体系或组合、在产物侧放多个物质；中栏下部是当前阶段的磁吸能量表达式画布。右栏为所选物质关系网、零点选择、来源证据、表达式诊断，以及反应物/过渡态/产物相对能量汇总。窗口尺寸不足时允许分栏折叠，但“应用/保存”、诊断、零点和整条路径始终可见。
- 路径轨道按用户确认的 **反应物 → 过渡态/中间体 → 产物** 顺序排列，拖动卡片时显示插入位置、阶段边界与有效吸附槽。轨道上方同时显示人可读的整条反应式，例如 `A + B → TS_AB → C + D`；它是用户确认的路径组成和标签视图，不替代用于计算的 AST。角色由用户选择，不从文件名、能量高低或关系边猜测。各物质、节点、entry、来源作业的 UUID 与路径名称均在详情中可核查。

#### L4.2 磁吸拼接节点表达式

1. 选中文件名只高亮。拖动或双击**具体作业及能量类型**，才生成候选物质卡；把卡拖到表达式画布的空槽时显示吸附预览，松开后才加入草稿。吸附仅对合法槽位生效，键盘可通过“添加组分 / 调整顺序 / 选择运算符”完成相同操作；触屏或无拖放环境可用按钮。画布至少支持来源项、显式 `+`/`−`、有限数值系数、括号组和带单位的能量偏移；不把相邻卡片默认为相加。
2. 吸附后生成或更新现有 `ExpressionDocument` AST，并调用既有表达式校验/预览链。单作业节点建立明确来源绑定；选择 Gibbs 时，该作业的 `SCF Done` 与 `Thermal correction to Gibbs Free Energy` 必须成对出现，组合结果附带两条来源行。若现有 `EnergyRef` 或 AST 不能原子地保证两项来自同一作业，先设计受约束的派生能量引用与迁移接口，不允许用户用两个自由卡片手工拼成一个看似同作业的 Gibbs 值。SCF 专项、热校正专项、高层 E + 低层 (G − E) composite 仍须各自明确标识和诊断，不能靠卡片邻接暗换能量类型。
3. 拖离卡片、改系数、换运算符、改顺序及撤销/重做均先作用于窗口草稿。无效或未完成表达式保留可编辑草稿并显示错误位置，不沿用先前有效结果，也不补零。磁吸画布无法无损表示的既有专家 AST 以“高级表达式”方式显示，提供专家文本编辑；复用 `ExpressionDialog` 时必须提供不自动调用 `controller.set_expression()` 的草稿模式，或在本窗口复用其编译/诊断组件。不得因打开专家编辑器而提前提交、扁平化或覆盖表达式。
4. 路径节点的角色、反应式计量系数与能量表达式分开编辑；多张物质卡拼接成一个体系能量节点时，关系网仍指向各自物质 UUID。画布明确区分“一个完整体系作业”（例如已计算的 `TS_AB`）与“若干独立作业的能量和”（例如 `A + B`）；不能因为反应式写着 `A + B` 就把完整体系作业再加一次。反应式系数只有在用户选择“按独立组分求和”并确认时才写入能量表达式；反过来也不从表达式加减号猜化学计量或关系边。共享计算节点的表达式编辑会影响所有引用路径，编辑前标明影响范围，并提供“创建独立节点”选项。

#### L4.3 整条路径的计算预设与自定义零点

1. 提供可手动选择的“相对能量路径”预设。用户先为反应物阶段 `R`、每个过渡态 `TS_i`、中间体 `I_i` 和产物阶段 `P` 指定物质组成、对应 Gaussian 作业、能量类型与表达式；预设为每一阶段生成 `ExpressionPurpose.SYSTEM` 的绝对体系能量 `E_R`、`E_TS_i`、`E_I_i`、`E_P`。默认零点选“反应物总能量”，形成 `E_0 = E_R`；主图只显示经组成配平、归一到同一零点的累计路径能量，局部步能量在详情中另列。所有值在内部保持 Hartree；显示时才按当前路径单位转换。
2. 零点可在路径顶层显式选择：**反应物总能量（默认）**、**本路径某个已构建阶段**、**另行磁吸拼接的自定义参考体系表达式**。高级选项允许输入带明确单位的手工绝对参考能量，但要在项目、图表、导出中持续标记“手工参考”，保存原始输入与单位，不能伪称 Gaussian 来源，也不能用于填补缺失作业值。零点必须通过现有 `ReactionPath.reference_expression` 表示，路径模式为 `relative`；同一路径仅减这一个参考一次。选择其他零点后，反应物也可能不再是 `0`，界面必须如实显示。
3. 预设公式在确认卡片与零点后自动生成并展示：`ΔE_R = E_R − E_0`，`ΔE_TS_i = E_TS_i − E_0`，`ΔE_I_i = E_I_i − E_0`，`ΔE_P = E_P − E_0`；同作业 SCF 与 Gibbs 热校正求和的路径标为 `ΔG`，SCF 路径标为 `ΔE`，单独选择 Gibbs 修正时须标为 `ΔGcorr`，不得冒称总自由能。过渡态的**相对能量** `E_TS_i − E_0` 与**局部活化势垒** `E_TS_i − E_前驱` 分栏展示；后者仅在用户明确选择对应反应步的前驱稳定态时计算/标注，不能因为零点默认是反应物就把二者混称。产物相对能量同样只相对选定零点，不按文件名推断反应热。
4. 用户手动选定或修改任一物质、作业、能量类型、系数、阶段角色、顺序或零点时，草稿预览通过既有来源校验、表达式求值和 `calculate_path` 重新计算。预览同时列出每阶段的绝对值、所选零点的绝对值、相对值、单位、依赖的文件/作业/来源行及诊断；点击“应用”后一次性更新路径节点与参考表达式，再由现有后台链生成正式图表。源作业缺值、异常终止、SHA 变化或类型不兼容时显示“不可计算”，不沿用旧值、不自动换作业或能量类型。
5. 预设只是用户操作的模板，不写死能量数值，也不扩大 `core/expressions.py` 的语法。反应物阶段表达式若在搭建器内修改，“反应物总能量”零点须在同一草稿事务中按新 AST 重建；选择某阶段为零点时同理。核心表达式不支持按 node UUID 动态引用，因此保存的是经校验的参考 AST 快照，预设元数据记录所选阶段和表达式签名；若其他入口改了该阶段表达式，须标出零点已不同步并让用户确认重建，不能悄悄继续用旧参考或重复扣减。`absolute` 与 `direct_difference` 旧路径继续按原语义打开；要使用本预设须经用户明确转换为 `relative`，不能混用两种模式的节点。
6. 参考零点不可用时，全路径相对结果均为无效并保留具体诊断；不得把该零点当作数值零。两条路径比较时显示各自的零点名称与参考表达式签名；若参考不同，明确标注“各自零点，纵向差值不可直接比较”，不暗中重定标或改动既有多路径比较算法。用户可主动选择同一个经核验的参考体系后重新计算。

**符号示例**：用户选择独立组分求和时，`A + B → TS_AB → C + D` 对应 `E_R = E(A) + E(B)`、`E_TS = E(TS_AB)`、`E_P = E(C) + E(D)`。若零点选反应物，显示 `ΔE_TS = E(TS_AB) − [E(A) + E(B)]` 和 `ΔE_P = [E(C) + E(D)] − [E(A) + E(B)]`；若零点改为产物，则同一绝对能量来源下重新减 `E_P`。这只是公式模板，实际数值必须来自用户选定且已核验的作业。

**现有能量入口核对及待修改点**：`core/parser.py` 分别读取 `SCF Done`、`Thermal correction to Gibbs Free Energy` 和 `Sum of electronic and thermal Free Energies` 三种原始行；当前默认 `gibbs_total` 直接采用日志的总量行，并未按用户指定规则重算。这是 L4 必须明确修改并验收的科学语义，不能描述成已经实现。目标算法为对同一作业的未截短原始 SCF 值和 Gibbs 热校正值做一次求和：`G_job = SCF_job + Gcorr_job`。日志总量行是独立核对值；允许其因打印精度与求和结果有可解释的末位差异，超出容差则暂停该作业的自动采用并展示三值、来源行及差额。缺任一加数时此计算量缺值；不能只因有日志总量行便暗中切换算法。高层 SCF 加低层 `(G − E)` 仅在用户显式选择 composite 模式时计算，并标注近似。

#### L4.3a 工作簿校准：组成配平、累计路径与局部差值

1. 用户提供的 `Energy_1b_7.30.xlsx` 是 L4 公式样例，不是可直接导入的作业身份清单。其 `F15=E15-E13-E11+E12`、`F22=E22-E13-E11+E12+E10-E3` 说明各阶段除了主体系还可能需要明确加入或扣除独立物质，且系数与符号会改变相对能量。搭建器须逐项展示“阶段组成账本”：物质 UUID、独立组分或完整体系、来源文件 SHA/作业 ID/来源行、能量类型、系数、正负号、原因及最终 AST。反应式的物质清单与能量账本分开展示，用户确认计量与能量口径后才允许纳入主图；不得从物质名称、星标或关系边自动生成补偿项，也不得把完整 TS 作业与其组成物重复计入。
2. **统一零点的累计能量为主，局部步能量另列。** 同一路径的主图各点须以相同的参照物质清单和一个 `reference_expression` 归一；预设应能把经确认的局部表达式代数展开成相同零点下的阶段绝对表达式，并只减零点一次。表的 `F58=E58-E50+F50` 展示递推；在 `F50=E50-E36-E3` 的前提下，F58 展开为 `E58-E36-E3`。这一等式只证明该表公式的代数关系，不自动证明各阶段化学组成相同。`F43`、`F49` 等局部参考值须明确标前驱/参考项；尚不能归一时只列入局部详情，主图标“无法归一”，不得把原 F 值当累计点、重复累计或填零。
3. 表的 C11:C16 与同名日志的 `SCF Done` 冲突，而 D/E 与日志热校正/Gibbs 总量相符；成因未获证明。用户已明确要求使用 `SCF Done + Thermo Correction`，因此**不能用表的 C11:C16 加 D 得到目标 Gibbs 值，也不能无提示照抄表 E**。对每个选定的真实作业，从同一已绑定文件与作业分别取 SCF 与 Gibbs 热校正，计算 `G_job`；用 Gaussian 总量行和表 E 分别交叉核对。必须保留 SHA、job ID、两条来源行、计算值、核对差值。表中 C 与该作业 SCF 不一致时标“工作簿来源冲突”；若使用者不能确认另一来源，这六个表 C 值不参与自动绑定。缺任一加数或核对差异超出明确容差时标为不可自动采用，不以表 E 或日志总量静默替代。
4. 表内 F 为空但 G 乘法缓存为 0 的行，不得变成有效的 `0 kcal/mol`。原表采用 `627.5095 kcal/mol/Eh` 的舍入因子；程序保持 `core/units.py` 的精确换算常数，以 Hartree 及合理显示容差比较。每个主图点和局部值都应可展开查看来源、完整表达式、零点、单位换算及诊断；不同理论级别、温度、溶剂或计算条件混用时显式标记并由用户处置，不自动认为可比。
5. 当前 AST 不以 node UUID 动态引用相对值。F58 一类递推在草稿中可保留前驱关系供解释，但落盘计算表达式须经可追溯的代数展开和循环检查，不能让前一步相对值伪装为绝对 `EnergyRef`。若 v1 模型无法同时可靠表达阶段组成、统一零点与局部差值，在改科学模型/SQLite schema 前提交最小接口及迁移方案，按第 4 节停下复核。
6. 用户提供的反应路径截图展示了以 CAT 为图示零点的多阶段曲线、分支与回汇、游离物质、单独标注的局部能垒箭头以及 `NOT FOUND` 过渡态。L4 须允许一个路径网络包含经用户确认的分支和回汇；每条边记录明确前驱、后继及该步计量/能量组成，绘图顺序不能冒充拓扑关系。图上统一零点累计纵坐标与箭头的局部差值分别计算，不能凭箭头长度或截图标注反推绝对能量。未找到的 TS 只保留可见占位与缺值诊断，不能插值、补零或自动创造一个势垒。截图数值用于理解展示方式，真实数值仍需来源计算与表达式核对。

#### L4.4 关系网与快速部署

1. 用户可在物质卡上显式建立、改名和删除前驱/后继边；从路径顺序建议边时也必须逐条确认。关系网显示来源作业是否可用，以及物质在多少计算节点和路径中出现。没有边的物质仍可独立入路径；删除物质时先展示受影响边和节点关联，绝不删除 Gaussian 来源文件。
2. 选中任一物质可点“从关系网部署”。窗口只在**草稿**中展示相邻候选、分支和可继续展开的路径；有多条出边、环、多个作业或多个能量类型时要求用户明确选择，不按名称或能量自动决策。已加星物质可在候选列表置顶、筛选并作为部署起点，但星标本身不生成新关系，也不自动指定路径角色、零点或反应式系数。
3. 部署预览逐项列出整条反应式、各阶段物质 UUID、将创建或复用的 node/entry、具体 job UUID、能量类型、表达式、角色、顺序、所选零点、预计相对能量、来源行及缺值/失效诊断。共享既有节点、复制为独立节点、新建节点必须由用户选择。确认后一次性应用到当前路径；可取消、撤销，不能半写入。关系网只帮用户选卡和组织顺序，数值仍由控制器调用现有计算链生成。

#### L4.5 在搭建系统中选择物质加星

- 物质库每张卡和关系网详情都提供“加星 / 取消星标”；先显示物质名、UUID 缩写与关联的作业供用户确认。二维及三维能量图上的真实节点仍可右键，但菜单项改为“选择物质并加星… / 在路径搭建窗口查看”：先以当前 `path_id + entry_id + node_id` 打开搭建窗口并高亮这个节点关联的物质，再由用户选择具体物质执行加星。一个节点关联多种物质时必须逐个选择，不能给整节点含糊加星。空白区、曲线、图例、投影/辉光层和已失效的旧 render_id 不得误触发。只读或后台忙时显示原因并禁用修改。
- 图上路径点只要关联了已加星物质，就显示不遮挡数值的星标；若有多种已加星物质，悬停提示列出名称和数量，点击可回到物质选择。共享物质在其他路径上也显示一致星标，这是物质级标记的预期行为。浅色、深色、选中、高亮与两条以上重叠路径均须可辨；键盘选中点也可打开同一物质选择。右键不触发普通左键选点、不改变相机。静态/离线导出显示已保存标记，离线页面不得提供看似可持久化的加星动作。
- 图表事件仍用现有 project_id、revision、render_id 校验；主线程收到合法事件后进入搭建系统，待物质 UUID 明确且控制器提交项目修订后才反馈成功。窗口草稿若因另一次物质加星而遇到修订变化，应合并这类**只改物质星标**的非冲突变化，或显式要求刷新；不得丢弃草稿或覆盖星标。

#### L4.6 应用、关闭与异常

- 窗口草稿绑定打开时的项目 UUID 与基础 revision。项目切换、路径/来源/表达式变化或后台忙碌时禁止直接应用旧草稿；提供重新载入并保留可复制内容。关闭未提交窗口时明确“继续编辑 / 放弃草稿 / 保留草稿”；保留的仅是带项目 UUID、基础 revision 和格式版本的编辑草稿，不能当作有效路径或计算结果，恢复时须重新校验。未提交内容不得半写入科学项目模型。
- 点击“应用”只表示控制器接受新修订；“保存到项目文件”须等待 `SessionBackend.save()` 确认并显示目标路径和 saved_revision。失败保留窗口和草稿、给出可重试原因。重新打开项目后，整条反应式、所选计算预设、零点及其表达式签名、各阶段表达式、关系网、物质身份、路径顺序、物质星标及图表状态必须一致。
- 文件缺失、SHA 不符、作业未正常结束、能量类型缺值和过期关系引用均显示现有来源/表达式诊断。关系边及星标可保留作历史编辑资料，但快速部署不得把失效来源当成可计算值。

**验收**：使用至少五个有明确来源的 Gaussian 作业，或标明为合成且每个数值可核对的受控夹具，搭出 `A + B → TS_AB → C + D`；反应物与产物按用户确认的独立组分求和，TS 按明确选中的完整体系作业计算。核对整条反应式的物质 UUID/计量系数、每阶段 AST、来源行与专家编辑器/现有计算链的结果一致；不重复计算完整体系。默认选择 `R` 为零点，逐项核对 `ΔE_R = 0`、`ΔE_TS` 和 `ΔE_P`；再改选产物或自定义组合为零点，核对全部相对值同步平移、绝对值和来源依赖不变。高级手工零点须带单位、醒目标记和可复算记录。分别核对 TS 相对零点的值与相对明确前驱的局部势垒；SCF、合成 Gibbs、单独 Gibbs 修正标签与缺值诊断不得混淆。依据工作簿固定输入复算 F15=+0.043120 Eh、F22=+0.040207 Eh、F58=−0.041063 Eh，并检查 F58 递推展开；这些仅是表公式回归值，真实路径须重新以同作业 SCF+热校正的未截短值计算，不以工作簿显示末位作为唯一真值。F43/F49 只能按已核对的局部参考显示。核对 C11:C16 来源冲突警告、空 F 的伪零拒绝、单位换算容差及阶段组成账本；未能配平或归一的点不得出现在统一零点主图。

为每个物质手工建立至少一条关系，走一条有分支的快速部署并核对候选选择、预览、取消和最终节点顺序；再建第二条不同颜色路径比较。给两条路径选择不同零点时核对“各自零点”提示，选择相同参考后核对比较结果。在搭建窗口给 `A` 加星，确认同一物质跨路径均显示星标；对含 `A + B` 的图上节点右键时须先选择具体物质，给 `B` 加星不能误改 `A`。二维/三维、深色/浅色及键盘操作均可见。保存 `.grproj`、关闭并从新进程重开，核对物质/关系 UUID、星标、整条反应式、预设、零点参考 AST、节点表达式、角色、颜色、来源和曲线。覆盖无效吸附、复杂专家 AST 往返、循环关系、零点阶段被修改后的签名失配、错误作业、缺能量、来源失效、修订冲突及保存失败。不得用演示数值冒充真实来源。

### L5：集成复核与交付

**目标**：四项功能能够在同一个项目中连续使用。

用一个含 B 元素的真实来源或标明为合成的受控夹具，执行“创建并命名项目 → 导入文件 → 拼接完整反应式与各阶段表达式 → 选择计算预设和自定义零点 → 建立物质关系并快速部署两条路径 → 在搭建系统中给物质加星并从图上核查 → 保存 → 退出 → 重开 → 改项目名 → 从最近移除/删除另一个测试项目 → 切换深浅主题”。核对项目、物质、关系边、节点、路径点、零点和科学值均未串线。只在功能完成后集中做一次桌面交互与截图复核，记录窗口尺寸、DPR、数据来源、通过项和限制。

交付时列出修改文件、实际验证命令与结果、截图路径、仍未满足的验收项。若某阶段未通过，停在该阶段修复；不要以旧 RF7/RF8 或打包报告替代本轮证据。

## 4. Luna 执行顺序与停止条件
