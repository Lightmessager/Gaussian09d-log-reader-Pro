# 架构决策（S0–S4）

## D001：Python 3.12 隔离环境

本机默认 Python 3.15 不用作初始发布基线。S0 使用已安装的 Python 3.12.14 建立项目 `.venv`，不修改系统 Python。依赖版本以实际安装和验证结果锁定；Python 版本范围暂为 3.12。

## D002：Qt Widgets 与局部 WebEngine

保留 Python 生态；采用 PySide6 Widgets 构建工作台，WebEngine 只承载图表。先检验页面、Plotly、WebChannel、事件和 frozen onedir。S0 不创建最终 UI 或业务控制器。

## D003：离线资源与接口

Plotly.js 从安装的 plotly Python 包提取并放入本地 vendor，记录 SHA256 和版本；Qt WebChannel 使用 Qt 内置 qrc 资源。本地页面不使用 CDN。WebEngine 请求拦截器阻断远程地址并记录请求，验证运行无外网依赖。资源通过 `__file__` 定位，兼容 PyInstaller onedir。

## D004：生产核心先于 UI

S0 交付数据/接口文档和有来源的合成 oracle；S1 才实现 parser/models/units。旧脚本仅作基线，不作为正确结果来源。工具可用 AST 提取旧 parse_log 进行基线扫描，不导入 Tkinter 主程序。

## D005：文件、节点与路径身份

文件 UUID 独立于名字；节点是体系公式；路径通过 PathEntry 引用节点并确定顺序。一个节点可被多个路径引用。相对值属于路径计算结果，不存回源文件。

## D006：S0 验收范围

合成样本覆盖多作业、单点、末作业失败、截断和指数数字。每个预期值带 1-based 行号，由人工给定并校验来源文本。尚无真实 Gaussian 日志，真实格式兼容性待 S1 校准。Qt 自测包含实际图表渲染及 QTest 鼠标点选，不能仅直接调用桥接回调冒充点选。

当前只具备 Windows 主机；macOS/Linux 记录为待各平台执行，不把 Windows 通过扩大为三平台已验证。

## D007：发布起步使用 onedir

PyInstaller 打包当前平台。先记录包体、WebEngine 进程/资源存在性和 frozen 自测，再考虑后续安装器。S0 包仅为可行性演示，不作为正式科研产品发布。

## D008：Windows ICU 解析与诊断包

首次 frozen 启动在 QtCore 导入阶段失败。PE 导入/导出核查发现 Qt6Core 要求 `ucnv_open` 等未加版本后缀的 API，但 PyInstaller 从宿主 Poppler PATH 选入了只包含版本化导出的 `icuuc.dll`。本机 Windows System32 的 ICU 包含所需 API，且源码运行正常。

Windows spec 排除该外部 ICU 及其 `icudt78.dll`，由 Windows loader 解析系统 ICU；不把 Poppler 资源带入应用。S0 保留 console=True 以便记录启动错误；最终正式 GUI 分发在 S9 另行配置。其他 Windows 版本的系统 ICU 可用性需在发布矩阵实测，不用本机结果推定最低支持版本。

参考：[Qt for Python 起步](https://doc.qt.io/qtforpython-6/gettingstarted.html)、[Qt WebEngine 本地页面](https://doc.qt.io/qtforpython-6/PySide6/QtWebEngineWidgets/QWebEngineView.html)、[PyInstaller 要求](https://pyinstaller.org/en/stable/requirements.html)。

## D009：S1 解析快照与身份

文件/作业/能量为不可变数据快照，不依赖 Qt；文件 UUID 由调用方持久化。作业 UUID5 依赖文件身份、起始行、解析器版本与按原始行构建的内容摘要。未改变的既有作业在追加新作业后保持 ID；改值或移位不静默沿用旧 ID。内容摘要不等于完整化学语义匹配，复杂重绑交给后续服务。

## D010：S1 作业边界与安全读取

新 Gaussian 启动、运行时 Link1 step 标记、正常/错误终止作为明确边界；内部 link 和优化周期不分割。未结束作业不会成为默认正常候选；SCF 收敛证据独立记录。支持精确显式作业选择，缺字段不借用其他作业。

读取为 64 KiB 上限分块、UTF-8/BOM 和原始字节 SHA256；单行超 64 KiB 跳过并诊断，路线限制 8192 字符、32 行，诊断每组最多 64 条。文件读中变化标 stale，取消/读取失败保留已取得证据但不投入新计算。参数或取消回调的编程错误向调用者抛出，不伪装成文件或 SCF 失败。

## D011：单位来源与兼容

S1 使用 NIST CODATA 2022 Hartree/Avogadro 和热化学卡路里定义推导统一换算，保留常数版本。舍弃旧脚本转换因子的末位舍入作为生产标准；S0 的固定演示与基准继续保留原值。差别仅在远低于通常显示精度的末位。所有内部计算以 Hartree 进行，转换拒绝 bool、NaN、Infinity 和溢出；S3 保存转换版本。

## D012：真实测试数据与验证范围

从 cclib 官方 BSD 3-Clause 仓库固定提交取得 G16 的单点、优化、频率完整日志，保留许可及 SHA256，人工核对能量/行号/元数据。ir/sp 拼接用于隔离测试并标为派生输入；原生 Link1 多步输出及 Gaussian03/09 尚待补充真实样本。S1 只承诺已验收的 SCF/Gibbs 字段和作业规则，不把最后 SCF 宣称为 CC/MP 或 ONIOM 体系总能量；识别 ONIOM route 时提示 composite_energy_requires_review。

## D013：S2 独立 DSL 与精确引用

采用有界 tokenizer/Pratt parser 和 JSON 语义树，直接支持引用 token 与带单位常量；不用 Python eval/exec，也不把文件名当 Python 变量。AliasIndex 精确绑定 EnergyRef，重复别名必须拒绝或明确去重；完整 UUID token 保留可复现性。直接 AST 同样验证，防止绕过文本入口的维度/深度/数值限制。

## D014：表达式目的与路径模式

ExpressionPurpose 明确 system/difference；CalculationMode 明确 relative/absolute/direct_difference。只在 relative 下统一扣减一次参考，不根据表达式符号猜模式。组合 Gibbs 需显式选择，提供高层 SCF 与同一低层作业 G/SCF 模板，保留近似警告；标准模式必须与路径能量类型一致。

## D015：缺失、草稿与来源诊断

保留旧 AST 用于历史和依赖排查，但无效草稿不产生新值。缺失数据、来源变更与未知作业返回 null/error；0×缺失值不能隐藏问题。异常作业计算默认拒绝，需显式 bool opt-in；SCF 明确未收敛仍拒绝。节点和参考分别保存来源依赖。条件冲突和未知分别告知，不自动作化学正确性判断。

## D016：不可变编辑预览

项目修改返回 ProjectChange，包含下一修订与影响/移除身份。calculate_preview 供审查，apply 校验项目和基准修订。节点共享与路径条目顺序分离；来源删除默认受保护，级联须显式选择，参考受影响时移除路径而非切绝对模式。未来撤销栈保留快照，控制器负责新修订单调增加。

## D017：S3 前固定别名命名空间

Project 保存 alias_bindings，与原始草稿一起恢复，避免重复文件名在恢复/重排后改变 token 绑定。草稿中完整可解析引用也参与删除保护。项目模型为持久化输入契约，snapshot_to_dict 仅作 JSON 投影；S3 仍需实现严格解码、版本检查和事务。

## D018：S3 SQLite v1 与严格快照

首个生产 schema 固定为 user_version=1/application_id=GRPR，八张表承载项目、来源/作业/能量、节点/路径/顺序和工作状态。嵌套 payload 逐字段按 dataclass 类型重建，AST 继续使用 S2 验证器；重复键、未知字段和非有限值拒绝。规范 JSON SHA256 作为跨表完整性校验，不作安全认证。保存/读取均用一致事务；不持久化被误当成当前值的计算缓存。

## D019：连接线程、写锁与修订状态

每个仓库单一执行器独占连接，DELETE journal + FULL synchronous，事务提交后才更新 saved_revision。操作系统持有型 sidecar 锁让第二实例只读，进程崩溃后锁释放；保留 sidecar 文件，避免删除后的竞争。较旧修订、相同修订不同内容、不同项目和外部修订冲突均拒绝。UI 在后台调用同步存储接口，不能因“仓库有线程”就在主线程等待 result。

## D020：独立恢复提交和升级前备份

RecoveryService 默认 1 秒防抖，恢复副本先提交、主项目随后提交，分别暴露修订及错误。失败保留重试请求；关闭 drain 并返回状态，UI 不得丢弃失败。未命名项目仅有 recovery_revision；启动提供恢复选择，不静默盖掉主项目。迁移先 SQLite backup，再在事务中执行 DDL/数据/版本；v0 是有明确标识的机制测试格式，真实生产版本从 v1 开始。Save As 也使用 backup API，已验证来源按新目录重建路径，源库不变。

## D021：历史证据与当前来源连接分离

load 精确保留保存时的科研快照，restore_session 另给来源连接报告和用于新计算的状态覆盖。缺文件仍能查原值/行号/历史公式；缺失、内容变更或无指纹不能作为当前有效来源。仅 SHA256 一致才可重连，保留 UUID；目录多候选不猜。恢复中断解析只报告，不自动继续任务。重解析是后续独立操作，不能按文件名/作业序号静默重绑。

## D022：偏好与可移植传输

QSettings 独立保存本机语言/主题/最近项目等，Qt 惰性导入使核心存储仍可在无 GUI 环境测试。科研工作状态存入 Project。grpack 用精确 SQLite 备份加自选且核对过指纹的日志；导入在暂存目录验证路径、资源上限、schema 和来源后再发布，失败不留下目标目录。只验证 Windows 本地文件系统，不把 Unix 分支和标准路径代码等同于已验收三平台。

## D023：S4 单一工作台和设计 tokens

采用顶部项目工具栏、左侧导航、中间表格/能量概览、右侧属性证据的 Qt Widgets 布局。浅色底、深绿导航、青绿强调色、统一字号/卡片/控件高度集中在 ui.theme；无需外部字体或图片服务。QAbstractTableModel 提供真实数据，首页支持继续项目与恢复副本。窄窗口收起属性和导航文字，减少最小高度；完整原生窗口截图验证宽窄布局。

## D024：后台用例与过期结果约束

SessionBackend 拥有仓库/恢复生命周期，ProjectController 用单工作线程 QThreadPool 串行执行耗时用例，主线程经 signals 接收不可变结果。每项任务携带 token 和项目 UUID/revision，避免旧工作覆盖当前状态。busy 时禁用语义变更；导入取消整批不合入，同时在解析分块检查。QTest 阻塞解析线程并检测主线程定时器，验证没有在界面线程等待。

## D025：ID 选择、显示状态和有证据的默认绑定

代理表格排序/筛选独立于 PathEntry 顺序，选择/上移下移都使用 node_id/entry_id。初次正常作业按路径类型选择，没有 Gibbs 可绑定正常 SCF 作业而维持 Gibbs unavailable；之后切换类型不重选作业。元数据、原值和行号集中显示在证据区。工作区保存页面、选择、搜索、列宽/排序和分栏，按显示字段类型恢复；未知科研状态字段保留。

## D026：会话切换、只读与关闭失败

恢复文件以项目 UUID 加会话 UUID 命名，避免同 UUID 的副本分支争锁。准备新资源、提交旧会话成功后才切换，打开失败仍保留工作。较新恢复副本必须明确选择，不静默覆盖。只读主文件不附在恢复写回链上，避免无编辑退出也触发保存错误；另存为可继续编辑副本。关闭先在后台更新/flush，成功后接受 Qt closeEvent；失败允许取消关闭或另存，只有已确认最新恢复副本时可明确选择保留恢复退出。

## D027：S4 原生概览与后续图表边界

S4 先以轻量 QPainter 能级概览贯通真实计算链，数值/模式/单位来自 calculate_path；无效节点不画值、连接线不跨缺点，点击联动表格，不自动断言势垒。当前工作台不依赖 WebEngine，S0 离线 Plotly 原型独立保留。S7 统一共享 PlotSpec 并加入完整离线 Plotly 2D/3D、视口和正式导出；S4 不复制 S0 的固定演示值或虚构三维面。CN/EN 与深色主题集中在 S5，公式/组分和完整节点路径编辑在 S6。

## D028：S5 本地化与外观属于本机展示偏好

中英文资源使用同一组中文源文案键，随应用离线打包；项目名、文件名、用户标签、公式和 ID 保持原样。首次语言偏好为 system，按 Qt 系统 locale 选择中文或英文；手动切换后保存明确选项。运行时切换只重绘控件、表头和提示，并恢复稳定 UUID 选择；不调用科学编辑接口，不增加 Project revision。浅/深主题集中在 QSS tokens，跟随系统按 Qt color scheme/palette 选择。语言和主题即时写入现有 LocalPreferences，不迁移 SQLite schema。

## D029：S6 单一文档和保守组分识别

组分编辑器和专家文本共用 S2 ExpressionDocument；不引入第二套求值器。只识别简单、有序线性组分与单个偏移；需要代数分配、常量合并、近似舍入或 composite 标记的表达式保留专家模式。来源以 UUID/作业/类型绑定，可搜索、双击或拖入物种，固定类型使用现有精确引用 token。

## D030：S6 草稿提交和来源预览

约 350ms 防抖，经现有串行 worker 提交有效表达式和无效草稿。错误草稿保留最后 AST，但不提供当前计算值。未完成的组分选择另存工作区提示，不能反过来充当 AST。编辑器关闭等待最新提交；位置从核心 Python 字符偏移转换为 Qt UTF-16 光标偏移。批量预览再次核查来源指纹，并且不提交候选修订，应用时检查 base_revision。

## D031：S6 会话撤销与解析屏障

最多 100 个不可变快照支持表达式、节点/路径、参考、标签、顺序、颜色/显隐及受保护来源删除的撤销/重做。恢复历史使用新的单调 revision；当前视图状态保留。打开项目、导入与重连会清空历史，避免恢复过期来源快照；历史本身不跨重启存储。

## D032：S6 共享节点与删除可见性

复制节点创建独立 node UUID，复制路径创建独立 path/entry UUID 并共享节点。界面明确共享节点编辑会影响所有引用路径；路径移除只清理所选且已无路径使用的节点。删除来源先展示节点与参考依赖，引用存在时必须明确选择级联；参考受影响路径按核心契约移除，不隐式改成绝对模式。

## D033：S7 共享 PlotSpec 与保守参考比较

worker 从当前结果生成不可变 PlotSpec，所有渲染器使用同一投影。JS 不求值、不扣参考、不换算科学值；无效点形成空缺。参考签名保留身份/AST/用途/组合模式/草稿，忽略位置，不证明代数等价。比较统一单位，不同参考警告并禁用跨路径差值。只有显式 TS、相邻前驱及用户点击才标局部势垒。

## D034：S7 本地生产页面与渲染代次

生产页面独立保留 S0 原型。协议 2 在 project/revision 外增加 render_id，防止同修订语言/主题旧回调覆盖新投影。Plotly.react 串行合并、监听器单次绑定；本地资源、远程拦截和文本转义并用。原生预览为加载失败/offscreen 后备，WebGL 缺失降级交互二维。标签引线不命中鼠标，避免遮挡节点点击和误拖锚点，文本保留拖动。

## D035：S7 项目视图与本机偏好

plot_state 白名单仅含视图；视口按项目/路径/单位/类型/模式/维度分别记录，标签按 entry UUID。复用 400ms 工作区合并和 S3 恢复，不升级 schema。只读探索只留本会话。语言/应用主题仍属本机偏好，忙碌时合并最新请求排队，修复旧任务覆盖最新语言的竞争。放大复用原面板，避免多份 WebGL 实例。

## D036：S7 审计结果包与纯 Agg helper

所有图和表共享投影，出图前核查来源，新目录输出拒绝覆盖。私有暂存完成后复制发布以继承目标 ACL，清单含哈希。CSV 文本防公式注入，JSON 保留原文。3D PNG 捕获 WebGL，HTML 携本地资源，不承诺 3D 纯矢量。原生测试发现 Qt/shiboken 导入钩子使 worker 导入 Matplotlib 扫描大量源码，故独立启动 Qt 导入前分派的纯 Agg helper，不修改第三方全局钩子。冻结入口/资源在 S9 实测。

## D037：S7 验收范围可证实

Windows 原生鼠标/WebChannel、scatter3d、导出与新窗口恢复单独验收，offscreen 不能替代 WebGL。100 次更新只证明结构/监听器不累积，不宣称完成内存和大文件测试。PDF 实际渲染核查中文/希腊字母与标签，窄窗口简化三维文字并提供放大。三平台与生产冻结包仍属 S9，S0 包不代表当前生产应用已可发行。

## D038：按用户指定 demo 恢复平滑高光曲线、圆形节点及 3D 光带
