# L4 阶段核查与科学接口边界（2026-10-17）

状态：**L4 代码实施基本完成；F15/F22/F58 路径级公式已覆盖。综合桌面视觉验收受当前运行环境阻塞：本地程序启动后没有可由 CUA 访问的窗口。**主图使用一个明确零点，局部步差按图边另行计算。分子式与计量完整时逐边核对元素守恒；缺失分子式时不猜测，每条边由用户独立确认并留下说明。

## 已实现且可复核的部分

- `core/parser.py`、`core/expressions.py`：`gibbs_total` 固定为**同一来源、同一 Gaussian 作业的最后 SCF Done + Gibbs 热校正**。结果依赖同时记录两条原始行；缺任一项就缺值。日志打印的总量只用于核对，差值超过 `1e-6 Eh` 时产生错误诊断并阻止自动采用。绝不从工作簿 C11:C16 的不一致数值自动绑定作业。
- `core/reaction_network.py`：在 SQLite v1 的 `workspace_state["reaction_network_v1"]` 中保存物质 UUID、绑定的来源/作业、星标、物质关系边、节点关联、路径阶段组成与独立能量账本、局部前驱、零点及参考 AST 签名；严格检查 UUID、大小、作业绑定、悬空历史关联和完整体系的额外项确认。删除来源/节点/路径后保留明确的历史关联。未核对“阶段组成与统一零点可比”的阶段不能自动应用。`NOT FOUND` 过渡态保留缺值占位，不生成能量。
- 物质卡可保存可选分子式；解析器支持元素符号、整数计数与嵌套括号。阶段有明确前驱且前后阶段所含物质均有分子式时，验证器按计量向量核对元素总数；不守恒时拒绝网络保存/路径应用并指出阶段及元素差。任一侧分子式缺失时不伪装为已配平，仍要求阶段组成核对确认与文字说明。该检查只证明元素向量守恒，不自动推断机理、物种身份或能量补偿项。
- 阶段支持多个前驱，应用时按稳定拓扑排序生成路径点；环路会被拒绝。每条阶段连接有独立 UUID、确认标记和说明；未逐边确认的连接不能预览/应用。旧线性数据确定性兼容为连接记录。二维/三维图表按实际有向边绘制，局部势垒仅认可真实入边；图形显示顺序不再冒充反应拓扑。
- 路径能量支持 `absolute` 与 `edge_recursive` 两种账本模式。递推模式要求每个根阶段有绝对能量账本、每条边有明确的有符号局部差账本；逐边将局部差加到前驱绝对表达式，回汇点以当前项目绑定的 Gaussian 作业计算每条入边累计值，差异超过 `1e-8 Eh` 即拒绝应用。路径零点只由路径参考表达式减一次，不将局部差误当绝对值，也不重复扣除前驱值。旧线性路径默认 `absolute`，不自动迁移到递推模式。
- 每条阶段连接单独保存反应物侧与产物侧计量列表；搭建器支持编辑两侧物质及正计量系数，已知分子式时按元素向量验证守恒，缺少分子式时保留逐边人工确认。旧网络缺少两侧字段时以连接端点当时的阶段组成生成兼容默认值，不改动旧节点表达式。
- `ui/reaction_builder.py`、`ui/main_window.py`：能量页入口和独立搭建窗口；物质卡可拖入阶段反应式及能量账本，阶段计量与能量系数分别编辑。可逐张卡指定来源/作业，添加多项正负能量账、选择完整体系或独立组分、编辑路径名/单位/颜色、预览统一零点相对值及明确前驱的局部步差。应用项目修订和保存 `.grproj` 是两个独立操作；修订冲突不会覆盖草稿，仅星标变化可在无冲突时合并。
- `core/plot_spec.py`、`profile_view.py`、`profile.js`、`scene3d.js`：二维/三维真实点的右键事件经 project/revision/render/path/entry/node 校验后打开对应搭建窗口；星标按物质 UUID 显示在点标签和悬停信息；手工参考零点显式标记；缺值 TS 在二维图中显示 `NOT FOUND`，三维视图显示缺值提示。局部势垒只按明确指定的前驱路径点计算。
- 物质关系网支持多选关系边，部署前列出目标阶段及共同前驱供用户确认；接受后创建平行候选阶段，未确认时不改写网络。三维图对缺值 TS 显示独立状态卡，不将其放到任何能量坐标；离线图像导出也绘制此状态卡。
